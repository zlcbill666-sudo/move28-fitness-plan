# MOVE 28 同行设计研究与下一阶段优化建议

> 研究日期：2026-08-10  
> 对照基线：线上提交 `b37ff2f2d61fcc6beefc9a157f456ac502ca07fa`  
> 研究对象：MOVE 28 当前 HTTPS 页面、Fitbod、Freeletics、Hevy、Caliber、Nike Training Club、Future Pro、Ladder、Apple Fitness、Keep、训记、乐刻运动。  
> 证据边界：产品能力与截图来自官方 App Store 或官方产品页；评分和评论量只作为产品覆盖度信号，不等于独立效果证据。

## 1. 结论先行

MOVE 28 现阶段最大的差距不是安全能力，也不是基础视觉质量，而是**产品信息架构仍像一张完整说明型长网页**。优秀同行普遍把体验压缩为：

```text
今天要做什么 → 一个主操作 → 单动作跟练 → 即时完成反馈 → 看见长期进步
```

MOVE 28 已经具备这条闭环所需的确定性计划、人工复核、当日状态、受控适配、反馈、顺延和完成摘要。下一阶段不应继续堆功能，而应把已有能力重组为一个“每天打开就知道做什么”的训练工作台。

**首要建议：先做“今日训练工作台 + 安全进度页”，再做媒体升级和语音陪练。**

### 1.1 证据分类

- **[O] 官方可验证能力**：来自官方 App Store 文案或官方产品页，只证明产品公开声明的功能。
- **[V] 官方截图观察**：来自 App Store 当前第 1–2 张截图，只描述可见的界面结构，不证明产品效果。
- **[H] MOVE 28 产品假设**：根据 [O]/[V] 和当前 MOVE 28 页面提出，必须由两人试用验证。

下文各竞品小节中的“观察”属于 [O]/[V]；“适合借鉴”和“不应照搬”属于 [H] 或 MOVE 28 已确定的安全边界。它们不代表同行产品已经被独立证明有效。

## 2. 当前 MOVE 28 设计诊断

### 2.1 已经做得好的部分

- 黑色、深蓝、荧光黄形成鲜明品牌识别，主 CTA 足够突出。
- 首页价值主张明确，强调低运动基础、低冲击和固定四周路线。
- “只要 3 步”降低理解成本。
- 今日任务、四周计划、动作库、安全、隐私均完整可达。
- 安全提示和删除数据拥有独立视觉层级，没有藏在细则中。
- 训练跟练已经支持单动作、横屏、完成摘要和下一次训练。

### 2.2 当前主要问题

1. **首次访问与回访用户共用同一长页面**  
   新用户需要品牌说明；已获批用户只想看今天做什么。当前两类任务没有分开。

2. **核心任务埋在长页面中**  
   首屏之后依次展示指标、三步说明、今日任务、四周计划、完整动作库、安全和隐私。动作库卡片很多，页面长度远超日常使用需要。

3. **“今日任务”不是整个应用的视觉中心**  
   成熟产品将今日训练、预计时长、训练状态和开始按钮放在首屏；MOVE 28 的品牌 Hero 比日常任务更强。

4. **进度反馈不足**  
   已有训练完成、反馈、周复盘等数据，但尚未形成用户能快速理解的周进度、计划完成情况和能力变化。

5. **视觉素材偏硬核、偏男性健美**  
   大量肌肉解剖和器械健美图与“普通用户、低基础、安全入门”的定位存在张力，可能让目标用户产生距离感。

6. **内容层级优于产品状态层级**  
   动作知识很完整，但“待问卷、待能力校准、待人工复核、可训练、需重新筛查”等状态还可以更像清晰的流程状态机。

## 3. 同行设计模式

## 3.1 Fitbod

**观察**

- 深色界面，单次训练直接展示目标肌群、动作数量、预计时长和动作列表。
- 训练记录页把组次、重量、休息计时和历史趋势放在同一任务流。
- 用亮色强调主操作和完成状态，数据密度高。

**适合借鉴**

- 今日训练卡一次回答“练什么、多久、几个动作、为什么”。
- 动作中保留历史表现和当前实际完成数据。
- 训练结束后把实际结果和下一次安排连接起来。

**不应照搬**

- 肌群恢复百分比等伪精确指标。
- 对普通入门用户展示过多重量、容量和图表。
- 未经人工复核的自动每日重排。

## 3.2 Freeletics

**观察**

- 大幅真人运动图形成强烈训练氛围。
- 今日训练以单张计划卡为中心，允许在进入训练前适配本次 session。
- 单动作跟练画面非常克制：人物、次数/时间、下一动作、进度条。

**适合借鉴**

- “今天条件变了”放在开始训练附近，而不是藏在设置里。
- 跟练页减少解释性噪声，保留动作、剂量、进度和安全停止。
- 当前训练完成百分比采用明确的离散步骤，不预测身体效果。

**不应照搬**

- 高强度、精英运动员视觉会压迫低基础用户。
- MOVE 28 自身不得把个性化或 session 调整扩展成开放式 AI 改处方，也不得把疼痛和伤病作为普通偏好处理；这是一条安全边界，不是对 Freeletics 当前实现的事实判断。

## 3.3 Hevy 与训记

**观察**

- 都把“快速记录”作为核心，不让课程内容压过训练任务。
- 组次完成使用明确勾选；历史记录、训练容量和动作趋势可回看。
- 导航稳定，训练、动作、历史、个人页职责清晰。

**适合借鉴**

- 完成动作时使用清楚的勾选和轻量反馈。
- 把进度页聚焦在计划完成、主观难度和能力变化。
- 动作库作为独立工具页，不在首页全部展开。

**不应照搬**

- 训练容量、最大重量和自由计划编辑不适合当前普通入门人群。
- 社交比较、排行和公开身体数据。

## 3.4 Nike Training Club

**观察**

- 真人教练和高质量场景照片建立可信感和陪伴感。
- 课程列表的核心信息固定：级别、类型、器械和时长。
- 内容分类清晰，但主视觉不会同时展示全部课程详情。

**适合借鉴**

- 用更包容的普通体型真人或统一插画替代部分健美解剖图。
- 今日卡固定显示：类型、时长、器械、强度、训练目的。
- 恢复提示采用一两句短文案，不扩展成内容门户。

**不应照搬**

- 以海量课程代替确定性计划。
- 为了内容感不断增加未经审核的动作或项目。

## 3.5 Caliber 与 Future Pro

**观察**

- Caliber 用“科学训练”建立信任，Future 用真人教练、持续反馈和责任感建立信任。
- Future 强调计划可以适应现实生活，并由教练持续复核。
- 两者均让“为什么这样安排”和“谁在负责”比动作数量更重要。

**适合借鉴**

- 显示人工复核的状态、时间和计划版本。
- 在用户接受调整后明确提示“需要再次复核”。
- 让用户知道当前计划是候选、已批准还是已失效。

**不应照搬**

- 不引入无法兑现的实时私人教练承诺。
- 不使用单一“力量分数”“身体分数”制造伪精确排名。

## 3.6 Ladder

**观察**

- 极强的“今天有一套现成计划”表达。
- 跟练页以视频、计时、当前组和进度为中心。
- 高对比品牌色和固定底部导航形成强应用感。

**适合借鉴**

- 回访用户默认进入今日工作台。
- 手机端提供稳定底部导航：今天、计划、进度、更多。
- 训练中保持一个主按钮，避免多个同级选择。

**不应照搬**

- 高强度竞技审美、火焰动效和连续打卡压力。
- 将周计划包装成每天必须完成的惩罚型任务。

## 3.7 Apple Fitness

**观察**

- 摘要页只呈现用户最关心的指标，可自定义和深入查看。
- 进度环、趋势和奖章视觉非常强，但依赖设备测量生态。
- 允许休息和暂停目标，减少连续打卡惩罚。

**适合借鉴**

- 周进度采用简单环或条形，不显示未经测量的热量。
- 明确允许恢复日、跳过和安全停止。
- 趋势只展示有真实记录来源的数据。

**不应照搬**

- 没有传感器时不能模拟活动环、卡路里或训练负荷。
- 不做奖章、排名和“闭环焦虑”。

## 3.8 Keep 与乐刻运动

**观察**

- Keep 的优势是多场景入口、明确“GO”主操作、中文语音陪伴和记录反馈。
- 乐刻运动首页承载门店、团课、私教、商城、社区和会员，商业入口很多。

**适合借鉴**

- 中文主操作要短且直接，例如“开始今天训练”。
- 训练过程可选语音提示，但不能替代屏幕安全信息。
- [H] 底部导航、周日历和卡片化进度可能降低中文移动端用户的查找成本，但本轮官方截图不能证明“中国用户更熟悉”；必须在两人任务测试中验证。

**不应照搬**

- 首页塞入课程、商城、社区、活动和会员权益。
- 现金激励、红包、排行榜、公开对比和身材焦虑。
- 用“AI 教练”扩大产品承诺，掩盖确定性规则和人工复核。

## 4. 值得借鉴的共同模式

1. **一个页面只解决一个核心任务**：今天练、训练中、训练完成、看进度。
2. **首页只有一个最强 CTA**：开始、继续或完成当前流程。
3. **回访用户跳过营销 Hero**：直接进入今日计划和状态。
4. **训练卡的字段稳定**：训练类型、时长、动作数、器械、强度、目的。
5. **训练中逐步披露**：动作媒体、当前剂量、进度、停止条件、下一步。
6. **完成反馈立即可见**：勾选、实际时长、完成动作、下一次安排。
7. **长期进度可视化**：周日历、计划完成数、主观难度、能力变化。
8. **教练感来自解释和责任链**，不一定来自聊天机器人。
9. **移动端使用稳定底部导航**，避免用户反复滚动超长首页。
10. **品牌素材与目标人群一致**：普通人、真实环境、低门槛动作，而不是健美模特。

## 6. 推荐方案：今日训练工作台

### 6.1 访问逻辑

```text
首次访问 / 无本地状态
  → 保留当前品牌首屏和“生成我的4周计划”

问卷或能力校准未完成
  → 直接显示当前步骤、预计剩余步骤和继续按钮

计划待人工复核
  → 显示复核状态时间线，不展示可训练 CTA

计划已批准
  → 默认显示今日训练工作台

计划失效或触发安全停止
  → 显示固定原因、下一步和重新筛查入口
```

### 6.2 今日卡片字段

- 第几周 / 星期几；
- 今日训练类型；
- 预计时长；
- 动作数量；
- 器械/地点；
- 强度范围；
- 一句“为什么今天练这个”；
- 主 CTA：`开始今天训练`；
- 次入口：`今天条件变了`；
- 状态：待复核 / 可训练 / 已完成 / 恢复日 / 已阻断。

### 6.3 手机端导航

```text
今天 | 计划 | 进度 | 更多
```

- `今天`：当前状态和唯一主操作；
- `计划`：四周日历与受控顺延；
- `进度`：真实记录和能力变化；
- `更多`：动作库、安全、隐私和维护信息。

桌面可保留顶部导航，但内容职责应与手机一致。

## 7. 推荐方案：安全进度页

只展示具有可信来源的指标：

- 本周计划训练数 / 实际完成数；
- 已完成动作和实际时长；
- 训练后反馈分布：过轻、合适、过重、疼痛；
- 每周复盘状态；
- 能力档案变化和重新评估时间；
- 计划版本与人工复核状态。

明确不展示：

- 热量和卡路里；
- 肌群恢复百分比；
- 身体年龄、燃脂效率、健康分；
- 未经测量的训练负荷；
- 连续打卡惩罚、排名和用户比较。

## 8. 视觉系统建议

### 保留

- 深色背景和荧光黄主色；
- 大字号标题；
- 黑白高对比；
- 橙红色安全警示；
- 清晰的卡片边界。

### 调整

1. 首页 Hero 只对首次访问者完整展示；回访用户收缩为品牌栏。
2. 将动作库从首页长列表移至独立页面或抽屉。
3. 减少解剖健美图比例，逐步替换为：
   - 不同年龄和体型的普通人；
   - 居家和普通健身房环境；
   - 统一、非性化、非竞技化插画；
   - 同一动作的标准版与受控变式并排。
4. 今日任务采用 1 张强卡片，不再与大量说明同级竞争。
5. 进度使用周日历、勾选和条形，不使用火焰、奖杯或压力型连续天数。
6. 安全停止按钮始终使用稳定位置和固定红色，不参与品牌动效。

## 9. 两人试用验证计划

样本只有 2 人，不使用转化率等伪统计。按任务成功和访谈记录验证：

### 任务

1. 打开页面后指出“今天要做什么”。
2. 在计划批准后 10 秒内找到开始训练入口。
3. 说出为什么今天安排这节训练。
4. 模拟精力不足，找到“今天条件变了”。
5. 训练中找到停止入口并理解适用情形。
6. 完成后找到实际完成内容和下一次训练。
7. 找到本机数据摘要和删除入口。

### 通过标准

- 2/2 用户无需提示完成任务 1、2、5、6、7；
- 2/2 能区分“待复核”与“可训练”；
- 无人把恢复日理解为漏练；
- 无人把进度条理解为减脂效果或身体评分；
- 任何安全入口误解都阻止扩大试用。

## 10. 实施顺序

### Phase A：先观察当前两人试用

- 不引入外部埋点；
- 使用现有问题记录模板和人工观察；
- 记录任务时间、错误点击、理解偏差和退出点；
- 只记录必要的非敏感可用性结论。

### Phase B：今日工作台与状态时间线

- 首次/回访用户分流；
- 今日卡；
- 人工复核状态；
- 手机底部导航；
- 动作库渐进披露。

### Phase C：安全进度页

- 周完成情况；
- 反馈和能力变化；
- 计划版本与复核记录；
- 无热量、无身体评分、无排行榜。

### Phase D：媒体与陪练升级

- 包容性视觉素材；
- 可选短语音提示；
- 更清晰的动作标准版/变式对照；
- 必须先完成版权、无障碍、静音降级和安全复审。

## 12. 最终建议

下一阶段不要先做账号、社区、排行榜、更多课程或更复杂的 AI。先验证并实施：

1. **回访用户默认进入今日训练工作台**；
2. **明确显示人工复核状态和下一步**；
3. **增加不含伪精确指标的安全进度页**；
4. **将动作库和长篇说明从日常主路径移开**；
5. **逐步替换偏健美、偏男性的素材**。

这条路线复用现有确定性引擎，不扩大处方能力；它**有望**改善任务查找、状态理解和日常回访意愿，但效果尚未得到证明，必须由两人试用的任务成功与访谈结果决定是否成立。
