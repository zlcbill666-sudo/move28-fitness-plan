# MOVE 28 产品演进知识库

> 最后更新：2026-08-10
> 当前线上基线：`b37ff2f2d61fcc6beefc9a157f456ac502ca07fa`
> 用途：保存长期有效的产品原则、研究证据、候选方向和否决边界，供后续调研、设计、实现与复审使用。

## 1. 产品北极星

MOVE 28 面向普通用户提供可解释、可复核、可执行的四周入门训练计划。产品不追求每天生成全新内容，而是通过有限输入、可信动作目录、确定性规则和反馈闭环，让用户在现实约束变化时仍能安全地持续训练。

核心承诺：

1. 安全规则始终优先于训练完成率和增长指标。
2. 目标决定训练方向，能力决定动作版本，风险决定安全限制，恢复反馈决定进度。
3. 每个差异化结果都应能解释，不能依赖黑箱推荐。
4. 正式训练入口必须经过规则校验和人工一致性复核。
5. 健康数据本地优先、最小收集、可查看、可删除。
6. 参与者使用可转发 HTTPS；ZIP 和 `file://` 仅用于维护和恢复验证。

## 2. 当前能力基线

截至基线提交，产品已具备：

- 健康风险筛查与 stop/manual_review/conservative/normal 路由；
- 三屏五项非极限能力校准；
- 家庭/健身房场景和器械约束；
- 可信动作目录、媒体、器械方案、排除项和受控变式；
- 确定性四周计划和完整 validator；
- capability revision、计划、人工审批和周调整 lineage 绑定；
- 单动作跟练、GIF、本地音乐和运行期停止；
- 周复盘及有限单变量调整；
- 本机存储、最小化诊断摘要和删除能力；
- 桌面、移动端、HTTP、断网和 `file://` 回归。
- 可信计划解释、训练前状态路由和当日受控适配；
- 训练后反馈闭环、安全顺延和人工复核 lineage；
- 横屏/大屏跟练、可信完成摘要和下一次训练提示。

## 3. 研究结论摘要

### 3.1 竞品真正值得借鉴的能力

#### Keep

可验证方向：课程和运动记录聚合、中文跟练表达、社区、智能硬件与运动档案。

可借鉴：

- 将完成度、主观难度、疼痛、恢复和能力变化汇总解释；
- 动作提示采用“目的—姿势—呼吸—停止条件”的短句结构；
- 可选的非打扰式语音提示。

不照搬：商城、开放社区、赛事和硬件生态。

#### Fitbod

可验证方向：依据目标、经验、器械、训练时长、历史表现和估算恢复生成力量训练；支持 RiR、动作偏好/排除和当日条件修改。

可借鉴：

- 将“不喜欢”“不会做”“无器械”“不适/疼痛”分成不同原因；
- 记录实际次数、负荷和通俗化余力；
- 当日条件变化只影响当前训练，不静默改写长期配置。

不照搬：伪精确肌群恢复百分比、默认力竭和未经人工复核的每日重排。

#### Nike Training Club

可验证方向：高质量跟练、渐进项目、恢复/睡眠/营养/心态提示、日程和大屏体验。

可借鉴：

- 每节课解释“今天为什么练这些”；
- 训练结束明确显示完成内容与下一次安排；
- 简短的恢复和睡眠提示；
- 横屏或大屏跟练。

不照搬：以内容数量取代计划执行闭环。

#### Freeletics

可验证方向：按时间、器械、空间、噪声、跑步条件和当日难度调整训练；支持顺延、动作替代和排除。

可借鉴：

- “今天条件变了”受控入口；
- 仅从审核动作图选择替代；
- 缺课顺延但不挤压恢复间隔；
- 疼痛与普通偏好严格分流。

不照搬：把伤病当作普通部位减量、开放式 AI Coach 改处方。

#### Google Fit

可验证方向：Heart Points、活动历史、跨设备汇总和容易理解的健康目标。

可借鉴：

- 将复杂计划指标翻译为普通用户理解的周目标；
- 强调步行和日常活动同样有价值；
- 只展示可解释的趋势，不声称精确测量身体状态。

不照搬：当前阶段不接入全量跨应用健康数据。

#### FitOn

可验证方向：多类型课程、个性化计划、冥想/营养、挑战、好友和多屏覆盖。

可借鉴：

- 多屏/离线跟练；
- 未来可选的单一责任伙伴，只共享完成状态；
- 按时长、无需跳跃等条件查看计划，但不能绕过处方自由拼课。

不照搬：疾病专项课程、排行榜、公开身体比较和默认社交同步。

### 3.2 竞品界面设计研究（2026-08-10）

本轮对照 Fitbod、Freeletics、Hevy、Caliber、Nike Training Club、Future Pro、Ladder、Apple Fitness、Keep、训记和乐刻运动的官方商店文案与截图，并审视当前 MOVE 28 HTTPS 页面。完整报告见：

- [同行设计研究与下一阶段优化建议](../research/2026-08-10-competitor-design-next-optimization.md)

官方可验证能力与截图观察：

- 多个产品公开提供个性化计划、今日训练卡、单动作跟练、训练记录、进度摘要或真人教练层；
- 官方截图普遍使用单一主操作、任务卡、稳定导航和训练完成反馈；
- Keep、乐刻等中国区产品同时证明多入口中文运动产品可能出现较高信息与商业密度。

MOVE 28 产品推断与待验证假设：

1. “今日任务 → 一个主操作 → 单动作跟练 → 完成反馈 → 长期进步”可能比当前长页面更适合日常训练主路径。
2. 当前页面可直接观察到首次访客与回访用户共用说明型长页面；将两者分流是否改善任务成功，仍需两人试用验证。
3. 回访用户默认进入今日工作台、动作库移出主路径、手机采用底部导航均是候选设计，不是已证明结论。
4. 进度页只能展示计划完成、实际时长、主观难度、疼痛反馈、能力变化和复核状态；不展示热量、身体评分或恢复百分比。这是产品安全边界。
5. “可信解释 + 人工复核状态 + 清晰下一步”能否提供足够教练感，是待验证假设，不引入开放式聊天机器人。
6. 偏健美、偏男性的解剖素材是否降低目标用户亲和感，需在试用中询问；包容性视觉作为候选方向。
7. 商城、社区、排行榜、连续打卡惩罚、红包激励和内容门户不符合当前产品范围，继续不做。

## 4. 长期更新方向

### 4.1 已完成或进入受控第一阶段的近期方向（截至 2026-08-10）

以下方向中，计划解释、训练前路由、训练后反馈、安全顺延和完成体验已经实现；动作替换仍只开放了经过审核的第一阶段器械适配：

1. 可信计划解释层
   - 为什么选择该场景、动作版本和难度；
   - 哪些能力约束影响了计划；
   - 为什么保持、减量或等待反馈。
2. “今天条件变了”受控适配
   - 已实现条件路由和器械不可用时的受控候选；
   - 时间不足、低精力在缺少审核减量表时返回不可适配；空间、噪声在目录缺少结构化标签时不开放；
   - 疼痛进入停止/降级/人工复核，不做普通替换。
3. 动作替换与排除原因码（部分完成）
   - 当前仅开放 `equipment_bodyweight_only`，并绑定独立执行清单、逐项 diff 和校验器；
   - 不喜欢、不会做、一般不适与疼痛仍需分别建立有限 schema 和策略，不能视为已实现。
4. 训练后反馈闭环
   - 过轻、合适、过重、疼痛；
   - 只通过确定性规则改变后续计划。
5. 安全顺延
   - 不叠加补课、不压缩恢复日、不制造第5周。
6. 跟练完成体验
   - 横屏/大屏、训练完成摘要、下一次训练提示。

### 4.2 中期：试用稳定后

- 周/月趋势与能力重新评估；
- 多个四周周期的显式衔接；
- 责任伙伴的最小披露模式；
- 加密导出、设备迁移和恢复；
- 目标路线扩展：习惯、减脂、力量、活动能力、心肺；
- 更多审核动作和媒体；
- 复核人工作台及批次管理。

### 4.3 后期：必须单独论证

- Health Connect、Apple Health、手表和步数接入；
- 账号及跨设备同步；
- 可解释 AI 助手，仅解释计划，不得改处方；
- 语音跟练；
- 特定人群路线，如孕产、骨健康、跌倒预防。

### 4.4 下一轮推荐：今日工作台与安全进度

1. 今日训练工作台
   - 首次访问保留品牌说明；回访用户直接进入今日状态；
   - 一张今日卡固定显示类型、时长、动作数、器械、强度、目的和唯一主 CTA；
   - “今天条件变了”紧邻开始入口，但不能绕过安全路由。
2. 人工复核状态时间线
   - 明确显示待问卷、待能力校准、待人工复核、可训练、已失效和需重新筛查；
   - 不把候选计划误呈现为可训练计划。
3. 安全进度页
   - 展示周完成、实际时长、反馈分布、能力变化和计划版本；
   - 不展示卡路里、身体年龄、训练负荷或惩罚型连续天数。
4. 渐进披露和移动端应用壳
   - 手机端优先使用“今天 / 计划 / 进度 / 更多”；
   - 动作库从首页长列表移到独立页面或抽屉。
5. 先在两人试用中验证任务成功，再实施视觉重构；不使用外部埋点。

### 4.5 当前明确不做

- 黑箱每日 AI 重新编排；
- 未经审核的自由动作生成；
- 公开排行榜、连续打卡惩罚和前后对比照；
- 肌群恢复百分比、身体年龄等伪精确指标；
- 拍照识别热量并声称精确；
- 未经临床治理的疾病、康复或饮食处方；
- 默认云端同步原始健康数据；
- 为增加内容量而加入大量未经审核课程。

## 5. 性别与生命周期个性化原则

### 5.1 当前决策

当前不新增必填“性别”，不建立男性版/女性版基础计划。

```text
目标层：用户主动选择
动作层：能力、疼痛、器械和偏好决定
剂量层：经验、相对强度和恢复决定
安全层：实际风险和生命周期状态决定
称谓层：可选，与计划引擎隔离
```

男女使用同一基本动作模式。相同目标、能力、风险、器械和恢复的用户，应得到相同计划规则。

### 5.2 需要直接询问、不能由性别推断的因素

只有在相应功能真正存在时，才逐步、可跳过地收集：

- 当前是否妊娠或处于产后恢复；
- 盆底症状；
- 骨量减少、骨质疏松、脆性骨折或压力性损伤；
- 明显影响训练的月经相关症状；
- 影响运动的激素治疗、近期手术、药物或医生限制；
- 围绝经期相关睡眠、疲劳和恢复问题。

敏感回答优先保存派生约束码，例如“需骨健康保守路线”，而不是长期保存详细生育、月经或手术记录。

### 5.3 不允许的默认推断

- 男性默认增肌，女性默认减脂；
- 男性练胸背、女性练臀腿；
- 女性默认轻重量高次数；
- 男性默认更激进进阶；
- 女性默认避开冲击；
- 根据姓名、头像、称谓或性别身份推断身体结构和风险。

### 5.4 公平性验收

构造两名用户：目标、能力、风险、器械和恢复完全相同，仅性别身份或称谓不同。生成计划必须相同。任何差异必须追溯到妊娠、骨折风险、疼痛、能力、恢复或医生限制等直接原因。

## 6. 安全、隐私与实现硬规则

1. 新输入必须是有限枚举或受界数值，拒绝自由文本进入处方引擎。
2. 新四周计划必须经过完整 plan validator；当日执行必须先重新验证源计划，再经过独立 `validateDailyExecution()`，不能把完整计划校验器当作单节执行校验器。
3. 动作替换必须保持训练意图、剂量边界、器械方案和 capability revision。
4. 疼痛、急性症状、医生限制不能降级成普通偏好。
5. 当日适配采用单次执行覆盖层，不得改写已批准计划或 weekly lineage；执行清单必须绑定 source plan/session、intake/capability revision、策略版本、固定原因码、逐项 diff 和批准状态。
6. 缺课顺延不得叠加同日训练、压缩恢复间隔或延伸出未经复核的新周期。
7. 不将恢复估算包装成测量结果；展示等级和原因，不展示虚假百分比。
8. 原始健康答案不得进入诊断摘要、分享、责任伙伴或营销数据。
9. 敏感字段遵循最小必要、渐进披露、允许跳过、本地优先和可删除。
10. 每项功能都要覆盖 unit、HTTP、移动端、`file://`、隐私和 hostile-input 边界。

## 7. 未来研究流程

每次研究按以下模板更新本文件：

1. 明确问题：用户任务、风险、产品阶段。
2. 优先一手来源：官方产品页、帮助中心、App Store、指南、共识和系统综述。
3. 分开记录：
   - 官方可验证能力；
   - 独立效果证据；
   - MOVE 28 的产品推断。
4. 对候选能力评分：用户价值、实现成本、新增安全风险、隐私成本、可审计性。
5. 检查是否能由已有机制扩展，避免新增重复引擎。
6. 明确“不做”和退出条件。
7. 形成有限 schema、失败关闭规则和测试矩阵后再实施。
8. 上线前必须通过规格、质量/安全独立复审和真实 HTTPS 验证。
